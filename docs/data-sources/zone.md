# nexdns_zone (Data Source)

Looks up a zone that already exists on your account by its domain name, so that records can be managed in a zone Terraform did not create.

## Example Usage

```terraform
# Manage records in a zone that already exists on the account, without
# adopting the zone itself into Terraform state.
data "nexdns_zone" "existing" {
  name = "example.com"
}

resource "nexdns_record" "www" {
  zone_id = data.nexdns_zone.existing.id
  type    = "A"
  name    = "www"
  content = "203.0.113.10"
  ttl     = 300
}

output "existing_nameservers" {
  value = data.nexdns_zone.existing.nameservers
}
```

## Lookup

The lookup matches the stored name exactly, so give the domain the way the
platform holds it: lower-case, without a trailing dot, and in punycode for an
internationalised domain. A name that matches no zone on the account is an
error.

## Schema

### Required

- `name` (String) Domain name to look up, as the platform stores it: lower-case, without a trailing dot, and in punycode for an internationalised domain. Any other spelling does not match and the lookup fails.

### Read-Only

- `created_at` (String) When the zone was created, as reported by the API.
- `id` (String) Identifier of the zone. Pass it as `zone_id` to `nexdns_record` and `nexdns_dnssec`.
- `nameservers` (List of String) Hostnames of the nameservers serving this zone.
- `status` (String) Status of the zone as the platform reports it, `active` for a zone that is serving.
- `type` (String) Type of the zone, `master` or `slave`.
