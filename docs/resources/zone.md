# nexdns_zone (Resource)

Manages a DNS zone on NexDNS.

`ns_group` is the one attribute that changes in place. Every other attribute forces a new zone, which deletes the zone together with all of its records – including records Terraform does not manage.

## Example Usage

```terraform
# A zone on the account's default nameserver group.
resource "nexdns_zone" "example" {
  name = "example.com"
}

# Delegate the domain to these at your registrar.
output "example_nameservers" {
  value = nexdns_zone.example.nameservers
}

# A zone pinned to a particular nameserver group. The valid values are the
# groups available on your account; changing this later moves the zone in
# place, keeping its identifier and its records.
variable "ns_group" {
  description = "Nameserver group slug, or null for the account default."
  type        = string
  default     = null
}

resource "nexdns_zone" "pinned" {
  name     = "example.net"
  ns_group = var.ns_group
}

# A secondary zone: transferred from your own primary server rather than edited
# here. Requires a plan that includes secondary zones.
resource "nexdns_zone" "secondary" {
  name      = "example.org"
  type      = "slave"
  master_ip = "203.0.113.53"
}
```

## Moving a zone between nameserver groups

Changing `ns_group` is an update, not a replacement: the zone keeps its
identifier and every record in it, and `nameservers` is refreshed with the
hostnames of the new group. Delegate the domain to those at your registrar
after the apply.

Every other attribute forces replacement, so changing a zone's `name`, `type` or
`master_ip` destroys the zone – with all of its records, including the ones
Terraform does not manage – and creates a new one. Read those plans before
approving them.

## Names as the platform stores them

Zone names are stored lower-cased, without a trailing dot, and in punycode for
an internationalised domain. A configuration that spells the same name any other
way is kept as written, so `Example.com` or `пример.рф` does not turn into
permanent drift.

A zone deleted outside Terraform drops out of state on the next refresh and is
planned for recreation rather than making the whole configuration unplannable.

## Schema

### Required

- `name` (String) Domain name of the zone, without a trailing dot, for example `example.com`. The platform stores names lower-cased and, for an internationalised domain, in punycode; a configuration that spells the same name differently is kept as written rather than reported as drift. Changing this forces a new zone.

### Optional

- `master_ip` (String) Public IP address of the primary server a `slave` zone transfers from. Required for `slave` zones, unused for `master`. Changing this forces a new zone.
- `ns_group` (String) Slug of the nameserver group that serves the zone. Omit it to use the default group on your account. The valid values are the groups available to your account, listed in the control panel and returned by the API. Changing this moves the zone to the other group in place: the zone keeps its identifier and all of its records, and `nameservers` is refreshed. Update the delegation at your registrar to the new nameservers afterwards.
- `type` (String) `master` for a zone whose records are managed here, or `slave` for a secondary zone that transfers from your own primary server at `master_ip`. Defaults to `master`. Secondary zones require a plan that includes them – see the [pricing page](https://nexdns.tech/pricing). Changing this forces a new zone.

### Read-Only

- `created_at` (String) When the zone was created, as reported by the API.
- `id` (String) Identifier of the zone, assigned by the platform. Pass it as `zone_id` to `nexdns_record` and `nexdns_dnssec`.
- `nameservers` (List of String) Hostnames of the nameservers now serving this zone. Delegate the domain to these at your registrar.
- `status` (String) Status of the zone as the platform reports it, `active` for a zone that is serving.

## Import

Import is supported using the following syntax:

```shell
# A zone is imported by its identifier, which the control panel shows on the
# zone page and the API returns as the zone's "id".
terraform import nexdns_zone.example zK7mPq2R
```
