# NexDNS Provider

The NexDNS provider manages DNS zones, the records inside them and DNSSEC
signing on [NexDNS](https://nexdns.tech) through its REST API. DNS becomes part
of the same plan as the servers it points at, so a hostname is never left
pointing at an address that no longer exists.

## Requirements

- Terraform 1.0 or later.
- A [NexDNS](https://nexdns.tech) account on a plan that includes API access, and
  an API token created under
  [API keys](https://nexdns.tech/settings/api-keys). DNSSEC and secondary zones
  are also part of the plan – see the [pricing page](https://nexdns.tech/pricing).

## Example Usage

```terraform
terraform {
  required_version = ">= 1.0"

  required_providers {
    nexdns = {
      source  = "nexdns/nexdns"
      version = "~> 1.0"
    }
  }
}

# The token may also come from the NEXDNS_API_TOKEN environment variable, which
# keeps it out of the configuration entirely.
provider "nexdns" {
  api_token = var.nexdns_api_token
}

variable "nexdns_api_token" {
  description = "NexDNS API token with the zones.read/zones.write and records.read/records.write scopes."
  type        = string
  sensitive   = true
}
```

## Authentication

The token is read from the provider block first and from the `NEXDNS_API_TOKEN`
environment variable otherwise:

```shell
export NEXDNS_API_TOKEN="nxd_xxxxxxxxxxxxxxxxxxxx"
terraform plan
```

Give the token only the scopes the configuration needs: `zones.read` and
`zones.write` for `nexdns_zone` and `nexdns_dnssec`, `records.read` and
`records.write` for `nexdns_record`.

## Two things worth knowing before the first apply

**A TTL belongs to a record set, not to a record.** Every value sharing a name
and a type is one set with one TTL, so two `nexdns_record` resources at the same
name and type must carry the same `ttl` – otherwise each apply resets what the
previous one set.

**Only `ns_group` changes a zone in place.** Every other attribute of
`nexdns_zone` forces replacement, and replacing a zone deletes it with all of
its records, including records Terraform does not manage. Moving a zone between
nameserver groups is the one edit that keeps the zone and its contents.

## Schema

### Optional

- `api_token` (String, Sensitive) API token used for every call. Create one under [API keys](https://nexdns.tech/settings/api-keys) on an account whose plan includes API access, and grant it the scopes the configuration needs: `zones.read` and `zones.write` for zones and DNSSEC, `records.read` and `records.write` for records. May also be supplied through the `NEXDNS_API_TOKEN` environment variable, which keeps the token out of the configuration; a value set here wins over the variable.
- `api_url` (String) Base URL of the REST API. Defaults to `https://api.nexdns.tech/v1`. May also be supplied through the `NEXDNS_API_URL` environment variable; a value set here wins over the variable.
